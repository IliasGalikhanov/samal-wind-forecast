# Архитектура SAMAL

Приложение запускается одним процессом Go, который обслуживает React и API. Каждый расчёт выполняется в дочернем Python-процессе. Для локальной демонстрации это упрощает установку и позволяет отменять обучение вместе с задачей.

| Компонент | Ответственность | Хранение |
|---|---|---|
| React / TypeScript | Импорт, настройки, графики, журнал | Предпочтения браузера |
| Go | HTTP API, валидация импорта, расписание, задачи | SQLite WAL |
| Python / CatBoost | Признаки, обучение, валидация, прогноз | Файлы запуска и версионируемый кеш моделей |
| Open-Meteo | Архив для обучения и актуальная погода | Кеш ответов и снимки |

Текущий прогноз явно передаёт `mode=live`. Исторический — `mode=dataset`, при необходимости `origin` и `replay_days`. Режим сохраняется в `request.json`; повтор текущего расчёта получает новый момент начала. Импорт и расписание используют настройки сервера. По умолчанию выбран live.

## Контракт запуска

`POST /api/turbines` создаёт турбину (`id` отсутствует/равен 0) или обновляет существующую (`id > 0`). Поля: `name`, `latitude`, `longitude`, `sample_minutes`, `rated_kw` (0 — не указано). Новый экземпляр начинает с пустого каталога. Миграция старой базы сохраняет турбины, задаёт интервал 10 минут и неизвестную номинальную мощность. После появления измерений интервал и мощность не меняются; часовой пояс станции также фиксируется. Имена и координаты редактируются.

`POST /api/imports/columns` принимает multipart `file` и `options` (JSON с `delimiter`), возвращает заголовки и автоматическое сопоставление известных названий. `POST /api/imports/preview` и `POST /api/imports` принимают одинаковые `file`, `turbine_id`, `options`: `delimiter`, названия столбцов `time`, `wind`, `power`, `temperature`, `power_unit` (`normalized`, `percent`, `kw`, `mw`). При отсутствии `options` исходный CSV остаётся совместимым. В БД сохраняются нормализованные измерения; снимок Python дополнен `sample_minutes`. Каталог и настройки восстанавливаются вместе с измерениями, включая совместимость с резервными копиями прежней схемы.

Одна установка использует общий часовой пояс для всех CSV. Координаты каждой турбины передаются Python в снимке конфигурации. Получаемые погодные признаки: скорость и направление ветра на 100 м, температура на 2 м. Произвольные дополнительные столбцы CSV модель не использует.

`POST /api/runs` принимает `{ "mode": "live", "horizon": 48 }`, возвращает ID и статус задачи. `GET /api/runs/{id}` возвращает этапы, результат и ошибку. `POST /api/runs/{id}/cancel` отменяет расчёт. `GET /api/runs/{id}/export` возвращает CSV. `GET /api/health` используется Docker.

`force_retrain: true` позволяет явно пересоздать пакет моделей. Обычно эта операция не нужна: изменение снимка измерений или конфигурации меняет ключ кеша автоматически. При совпадении ключа обучение и временная оценка пропускаются; исторические метрики загружаются вместе с моделями. Погодный API вызывается для нового прогноза, обучающие данные повторно не скачиваются.

Демосервис использует отдельный том и `SAMAL_DEMO=1`. Это настройка серверного процесса; пользователь не может подменить источник через POST `/api/runs`. База помечается `data_source=synthetic`; несовпадение режима и базы блокирует запуск. В демо запрещены изменение каталога, импорт и восстановление базы, а обычное приложение отклоняет синтетическую резервную копию. UI отключает соответствующие действия и объясняет, где работать со своими данными. Внешняя погода заменена подписью о синтетическом источнике. JSON/CSV содержат происхождение данных.

Go блокирует параллельный импорт/обучение, сохраняет снимок измерений и конфигурации, запускает Python с лимитом 30 минут. Python пишет события JSON в stdout, диагностические сообщения — в stderr. События и статус сохраняются в SQLite, stderr — в `worker.log`. Go независимо проверяет число строк, турбины, часы, origin, horizon и диапазон мощности перед присвоением статуса completed.

Временная ошибка внешнего API вызывает максимум три попытки. Ошибочный расчёт не заменяет последний готовый прогноз. При перезапуске приложения незавершённая задача получает failed; повтор запускается пользователем или расписанием. Очереди распределённых задач нет.

## Контейнер

Многоэтапная сборка: Node собирает React, Go создаёт бинарник с CGO_ENABLED=0, Python устанавливает зависимости из lock-файла. Финальный образ содержит бинарник, статику, ML-код и Python-окружение. Пользователь контейнера имеет UID 10001.

SQLite и артефакты находятся в `/app/runtime`, который подключён к постоянному Docker volume. Исходные CSV импортируются через API и не попадают в образ. Контейнер слушает 8080, Compose публикует порт на 127.0.0.1. SIGTERM завершает HTTP-сервер и отменяет расчёт. Архитектура рассчитана на один экземпляр приложения.
