# История разработки SAMAL

> Архив описания предыдущих версий. Упомянутые исходные CSV и детальные результаты экспериментов остаются непубличными и не входят в репозиторий. Метрики ниже получены на этих данных; публичная синтетическая демонстрация не воспроизводит их. Актуальные команды и формат CSV — в [README](../README.md), текущая архитектура — в [architecture.md](architecture.md).

Локальное приложение для прогнозирования нормализованной мощности двух ветровых турбин. Пользователь загружает CSV, приложение проверяет измерения, обновляет историю, сравнивает модели и выпускает почасовой прогноз на 24 или 48 часов.

Интерфейс на русском, казахском и английском языках, светлая/тёмная/системная тема, адаптация к узкому экрану. React и TypeScript отвечают за интерфейс, Go — за API, импорт, SQLite и управление расчётами, Python и CatBoost — за прогнозирование. Все данные хранятся на устройстве. Для получения погоды нужен интернет; измерения и обучение остаются на устройстве. Режим без внешней погоды можно выбрать в настройках.

## Запуск на Windows

На текущем устройстве приложение уже настроено. В PowerShell из этой папки:

```powershell
./start.ps1
```

Откройте http://127.0.0.1:8080. Пока приложение работает, оставьте терминал открытым. Остановка — Ctrl+C. Если порт занят, используйте `./start.ps1 -Port 8081`.

Для новой установки нужны Go 1.25+, Node.js 22.12+ или 24 LTS и Python 3.12. Установите зависимости и соберите приложение:

```powershell
./setup.ps1 -PythonPath C:/path/to/python.exe
./start.ps1
```

Путь Python можно опустить, если он доступен через PATH. Библиотеки устанавливаются в `.venv`, Go-кеш — в `.cache`, зависимости React — в `frontend/node_modules`. Версии зафиксированы в `go.sum`, `frontend/package-lock.json` и `ml/requirements.lock.txt`.

Для Linux/macOS создайте `.venv`, установите `ml/requirements.lock.txt`, выполните `npm ci && npm run build` в `frontend`, затем `go run ./cmd/server -seed data/raw`. Go автоматически выбирает `.venv/bin/python`. Проверка на этом устройстве выполнена под Windows; другие ОС отдельно не проверялись.

## Основной сценарий

1. Исходные CSV находятся в `data/raw/turbine 1.csv` и `data/raw/turbine 2.csv`. Первый запуск импортирует их автоматически; следующие запуски сохраняют существующую историю. На другом устройстве можно загрузить файлы через интерфейс.
2. На странице «Обзор станции» нажмите «Рассчитать прогноз». Агент выполнит четыре временные проверки с переобучением, выберет модель и проведёт исторический тест. Статус виден на всех страницах и в журнале. На исходном наборе этот процесс занимает несколько минут.
3. На странице «Прогноз мощности» доступны значения по часам, выбор турбины и выгрузка CSV. Начало прогноза по умолчанию — следующий час после последнего измерения. При выборе более поздней даты агент использует выбранную на валидации модель без свежих измерений: погодную модель или сезонный профиль. Без внешней погоды действует сезонный режим.
4. Через «Импорт данных» загрузите новый CSV и выберите турбину. При включённом переключателе новые записи автоматически запускают новый расчёт. Повторная загрузка того же содержимого пропускает дубликаты и не запускает лишнее обучение.
5. «Качество модели» показывает измеренные MAE и RMSE, сравнение моделей с погодой, без погоды и базовых прогнозов, оценки каждого временного отрезка и ошибки отдельно по турбинам и горизонтам 1–24 / 25–48 часов. «Журнал агента» сохраняет все версии и причины решений. Старые версии результатов остаются доступны со своими метриками.

Несмотря на названия предоставленных файлов, фактических измерений за февраль 2026 года нет. Приложение не сообщает точность февральского прогноза без факта. Внешняя погода теперь разрешена пользователем и автоматически загружается через Open-Meteo Previous Runs API по координатам обеих турбин. Исходные CSV остаются единственным источником фактической мощности.

Цель — средняя нормализованная активная мощность часа, от 0 до 1. Интерфейс показывает её в процентах. Это не энергия в МВт·ч. Номинальные мощности и точная формула нормализации не предоставлены; суммарная выработка станции не выдумывается.

Временные отметки CSV сохраняются в исходном виде. Для совмещения с погодой пользователь выбрал рабочее допущение `Asia/Almaty`; происхождение часового пояса CSV не подтверждено. Настройка допускает также UTC. Историческое изменение смещения Казахстана учитывается базой часовых поясов; неоднозначный повторный час исключается из обучения. Принято рабочее допущение: отметка обозначает начало 10-минутного интервала. Час пригоден как целевое значение и лаг только при наличии всех шести измерений. Частичные часы и отсутствующие интервалы не подменяются нулями, интерполяции через будущие значения нет.

## Погода и автоматический цикл v3

По умолчанию включён `weather-offset-4fold-v3`. Go запускает получение погоды, подготовку признаков, обучение, временное сравнение, анализ полноты/границ прогноза и сохранение результата. Ошибка погодного API вызывает до трёх попыток; при отсутствии полного погодного горизонта запуск завершается с понятной ошибкой и сохраняет предыдущие результаты.

Источник — [Open-Meteo Previous Runs API](https://open-meteo.com/en/docs/previous-runs-api), модель DWD ICON Global. Используются прогнозные скорость и направление ветра на 100 м и температура на 2 м. Высота ротора неизвестна; 100 м — высота погодного признака. Обе координаты могут попадать в одну ячейку погодной сетки; это видно в манифесте. Данные имеют лицензию CC BY 4.0; бесплатный API предназначен для некоммерческого использования. См. [условия провайдера](https://open-meteo.com/en/terms).

Для целевого часа выбирается `previous_day1`, `previous_day2` или `previous_day3`: `ceil((target_utc - origin_utc + 12 часов) / 24 часа)`. День 0, фактическая погода и реанализ не используются. По определению провайдера прогноз имеет как минимум указанную заблаговременность; дополнительно оставлены 12 часов на публикацию. **Это консервативная граница доступности, а не доказанное точное время выпуска:** API не возвращает фактические метки публикации каждого прогноза. В `weather-forecast.json` сохранены UTC-цель, выбранное смещение и верхняя граница времени инициализации. Для строгого доказательства поминутной доступности потребовался бы архив выпусков с журналом публикаций.

Сравниваются три CatBoost MAE: история + погодный прогноз (98 признаков), только календарь/турбина/горизонт + погода (12 признаков), только история (92 признака); также последнее измерение и сезонный профиль. Во всех проверках сравниваются одинаковые часы с доступной погодой и фактом. Четыре 14-дневных отрезка определяют основной метод, а сравнение погодной модели без истории и сезонного профиля — резерв для устаревших измерений. После выбора оцениваются последние 14 дней. Для обучения используются только метки до соответствующей границы и до двух лет доступной истории с архивной погодой.

В интерфейсе:

- «Рассчитать прогноз» выполняет полный цикл на 24/48 часов.
- «Рассчитать 28 ежедневных прогнозов» повторяет прогноз с шагом сутки от выбранного начала. На исходных данных это 1–28 февраля 2026: 28 запусков × 48 часов × 2 турбины = 2 688 строк. Последний 48-часовой горизонт захватывает 1 марта. Измерения остаются зафиксированы на 31 января; будущий факт и выдуманные измерения в лаги не подставляются. Полный CSV сохраняет origin, целевой час, горизонт, турбину и применённую модель.
- В «Настройки → Погода и автоматический цикл» выбран часовой пояс, режим начала и автообновление. В историческом режиме начало берётся после последнего CSV; в текущем — следующий час от системного времени.
- В текущем режиме при включённом автообновлении сервер повторяет цикл каждые 6 часов. Сервер должен работать; браузер может быть закрыт. Исторический режим не запускает расчёты по часам. Новые измерения запускают цикл через существующий переключатель авторасчёта при импорте.

Полученные архивы кешируются в `runtime/weather-cache`. Каждый запуск содержит `weather-training.csv`, `weather.json`, `weather-forecast.json`, погодные модели, `request.json` и `replay.csv`. Манифест фиксирует запросы, координаты, время загрузки, погодную модель и SHA-256. Числовой снимок погоды входит в резервную копию вместе с серверными настройками; общий повторно загружаемый кеш не включается. Старые резервные копии поддерживаются.

Реальная проверка v3 на предоставленных данных (48 часов):

| Модель | MAE четырёх проверок, п.п. | MAE 18–31 января, п.п. |
|---|---:|---:|
| Погода + история — выбранная | 19,03 | 19,50 |
| Только погода — резерв без свежих измерений | 19,32 | 18,42 |
| Только история, в этом сравнении | 30,15 | 29,80 |
| Последнее измерение | 33,17 | 39,36 |
| Сезонный профиль | 34,57 | 30,79 |

Январский тест уже анализировался при разработке. Эти числа — повторная историческая оценка при допущении о часовом поясе; точность февраля не подтверждена без фактических измерений. Основная модель выбрана по четырём проверкам, хотя погодная модель без истории оказалась лучше на последующем январском тесте.

## Проверка качества без внешней погоды (v2)

В конвейере `rolling-4fold-rich-lags-v2` последние 14 дней общей истории оставлены для исторического теста. Перед ними расположены четыре последовательных отрезка по 14 дней. Перед каждым модель заново обучается только на более ранних данных, затем строит суточные прогнозы на соответствующем отрезке. Отдельные прогнозы на один целевой час от разных запусков считаются отдельными примерами; график показывает первые 24 часа каждого запуска без повторов.

Сравниваются CatBoost с функциями потерь RMSE и MAE, сохранение последней полной почасовой мощности и сезонный профиль «месяц × час». Победитель определяется по объединённой MAE четырёх проверок; учитываются только горизонты до запрошенных 24 или 48 часов. Выбор фиксируется до теста. Для теста модели обучаются до его начала и больше не обновляются; новые измерения для лагов становятся доступны по мере прохождения имитируемого времени. Обучающие цели и сезонный профиль всегда ограничены предыдущей историей. Простая модель остаётся допустимым победителем, если она выигрывает проверку: изменения графика сами по себе не являются критерием качества.

CatBoost использует 92 числовых признака: турбину, горизонт, циклические час/день года, лаги мощности, ветра и температуры до 72 часов, средние/разброс/минимумы/максимумы за 3/12/24/72 часа, изменения мощности и ветра за 3/12 часов и полноту последнего дня. Будущие скорость ветра и температура не используются. Обучающие origins имеют шаг 12 часов и цели 1–48 часов; берётся до двух лет истории. Параметры зафиксированы: 320 деревьев, глубина 6, `learning_rate=.05`, `l2_leaf_reg=8`, `random_seed=42`, `thread_count=4`. Результат содержит параметры и список признаков.

После проверки выбранный CatBoost переобучается на всей доступной истории для итогового прогноза. Если выбрана базовая модель, используется её актуальная версия и интерфейс явно помечает результат как базовый прогноз. При недостаточной свежести или полноте данных действует сезонный режим. Его прогноз не получает автоматически приписанную точность выбранной модели: значения MAE относятся к указанному историческому тесту.

Отрезок 18–31 января 2026 уже анализировался при разработке v1 и v2. Хотя алгоритм не использует его для выбора модели, повторная проверка на нём не является новым независимым подтверждением качества. Такая проверка возможна только после получения новых фактических измерений. Изменения параметров v2 не подбирались по ошибке этого повторного теста.

## Агент и хранение

Агент реализован в Go как последовательность программных действий с правилами выбора модели и резервного режима. Он не использует LLM. Это агент с программными правилами: он выбирает инструменты получения погоды, повторяет неудачные запросы, проверяет доступность входов на момент прогноза, выбирает модель и резерв по валидации, проверяет выходы и реагирует на импорт/таймер. Наличие LLM не заявляется; формальную трактовку Agentic AI определяют организаторы.

Один расчёт выполняется за раз. Go создаёт неизменяемый CSV-снимок, запускает локальный Python-процесс, записывает этапы, проверяет JSON-результат и сохраняет версию. Во время расчёта импорт заблокирован, чтобы входные данные не менялись. Ограничение расчёта — 30 минут, включая первичную загрузку погоды. При перезапуске сервера незавершённый запуск помечается как прерванный, его можно повторить.

Импорт выполняется транзакционно. Ключ измерения — `(turbine_id, time)`, а не колонка `ID`. Полные дубликаты пропускаются. Разные значения по одному ключу отклоняют весь файл. Проверяются названия колонок, шаг 10 минут, конечность чисел, нормализованная мощность 0–1, ветер 0–100 м/с и температура −100…100 °C. Диапазоны ветра и температуры — широкие технические границы проверки ввода, не характеристики этих турбин.

`runtime/energy.db` хранит измерения, загрузки, запуски и результаты. `runtime/uploads` хранит исходные загрузки. `runtime/runs/<id>` содержит снимок, SHA-256 в результате, модели, `result.json` и журнал Python. Резервные копии создаются в разделе «Настройки» без остановки сервера. Исходники в `data/raw` не изменяются.

## Возможности интерфейса v2.0

- Русский, казахский и английский интерфейс; локализованы числа, даты, графики, названия моделей, уведомления и этапы расчёта. Исходные имена файлов и подробная диагностика сервера сохраняются без перевода.
- Светлая, тёмная и системная темы. Системная тема реагирует на изменение темы ОС; цвета графиков также адаптируются.
- Настройки горизонта 24/48 ч, автоматического расчёта после импорта, уведомлений и числа строк на странице. Настройки действуют в текущем браузере; их можно экспортировать и импортировать как JSON.
- Сохранение страницы, турбины, периода истории, горизонта и открытой версии прогноза. Эту возможность можно отключить.
- Центр уведомлений хранит до 200 последних событий на устройстве: поиск, прочтение, очистка, переход к результату. Журнал агента хранится в базе отдельно. Для событий во время закрытого браузера показываются изменения ранее наблюдавшихся запусков при следующем открытии.
- Поиск, фильтры по турбине/статусу, диапазону дат, сортировка и пагинация историй. Даты фильтров и время событий используют часовой пояс браузера. Время измерений никогда не сдвигается.
- CSV сначала проверяется без сохранения: период, первые пять строк, число новых записей, дубликатов и конфликтов. Сохранение повторяет проверку транзакционно. Прогресс передачи файла измеряется браузером, затем показывается этап обработки.
- Две версии прогнозов сравниваются на пересечении целевых часов выбранной турбины. Есть график, таблица, среднее абсолютное изменение и CSV. Разность версий не выдаётся за ошибку относительно факта.
- Активный расчёт можно отменить. Процесс Python останавливается, запуск получает статус `cancelled`, предыдущие прогнозы сохраняются. Из журнала доступен повторный запуск.
- Индикатор возраста данных. Оценка приблизительная из-за неизвестного часового пояса исходных файлов; прогноз по умолчанию начинается после последнего измерения.
- Подсказка для первого запуска, управление с клавиатуры, фокус в диалогах, ссылка перехода к содержимому, увеличенный текст и уменьшение анимации. Интерфейс адаптирован к узким экранам.

### Резервные копии и восстановление

В «Настройки → Резервное копирование» скачайте ZIP. В нём находятся согласованный снимок SQLite, оригиналы загрузок и файлы расчётов. Копирование, импорт и расчёт взаимоисключаются. Настройки и уведомления браузера не входят в архив; настройки экспортируются отдельно.

Для восстановления выберите ZIP (до 512 МБ, до 2 ГБ после распаковки), нажмите «Проверить архив», просмотрите число измерений и результатов, затем подтвердите замену. Проверяются версия, структура, целостность базы и пути файлов. Перед заменой создаётся `runtime/recovery.zip` — полная копия состояния до последнего восстановления. Её можно скачать в том же разделе даже после перезагрузки страницы. Следующее восстановление заменяет эту страховочную копию; для хранения нескольких версий скачивайте архивы отдельно.

При ошибке транзакция откатывается и прежние файлы возвращаются. Для переноса на другое устройство сначала установите SAMAL через `setup.ps1`, затем загрузите архив. Архив не включает исполняемый файл и зависимости Python/Node.

## Разработка и проверки

```powershell
./check.ps1
```

Для разработки интерфейса запустите сервер Go и отдельно `npm run dev` из `frontend`. Vite проксирует `/api` на порт 8080. Go раздаёт готовую сборку из `frontend/dist`; после изменений в React для основного порта требуется `npm run build` и обновление страницы.

Проверки покрывают откат конфликтного импорта, повторный импорт, разделение турбин, неверные значения, сохранение пропусков, запрет использования будущих измерений, границу обучающих меток и построение сезонного профиля только по прошлому. React проверяется TypeScript и production-сборкой; основные пользовательские сценарии проверены в браузере.

Дополнительная интеграционная проверка использует временную базу, импортирует последний реальный день как новые данные, дожидается автоматического расчёта Python и проверяет сезонный режим для отстающей турбины. Основную базу пользователя она не меняет:

```powershell
$env:SAMAL_INTEGRATION = '1'
go test ./internal/app -run TestUploadRealDataPipeline -v -count=1
Remove-Item Env:SAMAL_INTEGRATION
```

Первый запуск на предоставленных данных: выбор на 4–17 января 2026 года, тест на 18–31 января. По валидации выбрана модель последнего измерения (MAE 28,24 п.п.). На тесте её MAE составила 39,36 п.п.; у CatBoost — 31,36 п.п., у сезонного профиля — 31,14 п.п. Победитель не заменён по результатам теста. Это показывает нестабильность качества при отсутствии будущей погоды, а не подтверждает пригодность прогноза для производственного планирования. Эти значения относятся к исходной версии данных и изменятся при новых загрузках.

### Повторная проверка: версия 2

На тех же данных для горизонта 48 часов версия `rolling-4fold-rich-lags-v2` выбрала CatBoost с функцией потерь MAE. Используются 92 признака из прошлых измерений; перед каждым из четырёх проверочных отрезков модель обучается заново.

| Модель | MAE на четырёх отрезках, п.п. | MAE 18–31 января, п.п. |
|---|---:|---:|
| CatBoost · MAE | 31,32 | 30,25 |
| CatBoost · RMSE | 32,49 | 30,61 |
| Последнее измерение | 33,17 | 39,36 |
| Сезонный профиль | 34,57 | 30,79 |

Отдельный расчёт для горизонта 24 часа также выбрал CatBoost · MAE: на четырёх отрезках MAE составила 29,76 п.п. против 30,14 п.п. у последнего измерения; на историческом январском тесте — 28,56 против 36,16 п.п. Преимущество на валидации для 24 часов небольшое, поэтому устойчивость улучшения на будущих периодах не подтверждена. Результаты сохранены в `runtime/research-v2-24/result.json`; результат запуска 48 часов доступен также в журнале приложения.

Итоговый прогноз на 1–2 февраля меняется от 23,9% до 41,4% для турбины 1 и от 23,4% до 39,0% для турбины 2. Изменчивость графика сама по себе не подтверждает качество. Ошибка около 30 п.п. остаётся большой; январский тест уже рассматривался при разработке, поэтому это повторная историческая оценка, а не новая независимая проверка. Для подтверждения качества на прогнозируемом периоде нужны последующие фактические измерения, которых в предоставленных CSV нет.
