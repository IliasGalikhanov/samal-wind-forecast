## Проверки CI

В `.github/workflows/ci.yml` два независимых job. Первый проверяет Git index и историю на приватные файлы и распространённые форматы секретов, устанавливает зависимости, проверяет Go, Python и React, выполняет полное синтетическое обучение и повторный прогноз с программно запрещённым обучением. Второй собирает контейнер только из исходников, запускает пустую базу, импортирует короткий синтетический CSV, проверяет API и повторяет чтение после перезапуска.

CI не обращается к погодному API и не требует исходных CSV. Установка зависимостей и сборка образа требуют сети. Реальный ML-сценарий запускается отдельно с собственными измерениями и интернетом; исходный датасет проекта не распространяется.

В корне репозитория `.github`, `Dockerfile`, `go.mod` и `frontend` находятся на первом уровне. Актуальный статус удалённых проверок: [GitHub Actions](https://github.com/IliasGalikhanov/samal-wind-forecast/actions).

## Полный синтетический сценарий

```sh
python scripts/demo.py --verify
```

Команда генерирует 44 064 измерения (153 дня × 144 интервала × 2 турбины), синтетическую погоду, обучает обычный набор CatBoost-моделей, сравнивает их на четырёх временных отрезках и отдельном историческом периоде, затем строит два прогноза по 96 строк. Во втором запуске функция обучения заменена на отказ: тест завершится ошибкой, если сохранённая модель не переиспользована. Начала прогнозов фиксированы: 1 и 2 января 2026; это демонстрационная история, а не текущий прогноз реальной станции.

Артефакты сохраняются в `runtime/demo-cli/`, краткий отчёт — `verification.json`. При повторном запуске команды первый прогноз тоже может использовать кеш. Для проверки с пустым кешем задайте новый каталог через `--output runtime/demo-new`.

Интерактивное демо: `docker compose --profile demo up --build -d --wait demo`, затем localhost:8081. Использует ту же синтетическую историю и вымышленную погоду на текущие часы. База в отдельном томе; пользовательская история не копируется.

## Чистый запуск

Для независимой проверки используйте отдельную копию исходников без `.venv`, `.cache`, `runtime`, `node_modules` и `dist`. `.dockerignore` также исключает эти каталоги из контекста сборки. Запускайте новый Compose project, чтобы получить пустой том:

```sh
SAMAL_PORT=8081 docker compose -p samal-check up --build -d --wait
python scripts/smoke.py --url http://127.0.0.1:8081
docker compose -p samal-check restart app
SAMAL_PORT=8081 docker compose -p samal-check up -d --wait
python scripts/smoke.py --url http://127.0.0.1:8081 --verify-persistence
docker compose -p samal-check down
```

В PowerShell вместо префикса `SAMAL_PORT=8081` выполните `$env:SAMAL_PORT='8081'`. `smoke.py` предназначен только для новой тестовой установки: проверяет пустоту базы перед импортом, отключает автообновление и создаёт три турбины со своими координатами и добавляет по 12 синтетических строк. Этот набор не подходит для обучения.

## Реальный расчёт

В обычной установке настройте свои турбины и импортируйте их CSV, затем запустите `python scripts/forecast.py --mode live --horizon 48`. Скрипт использует тот же HTTP-контракт, что UI, показывает этапы, ждёт до 1900 секунд и сохраняет `result.json` и `forecast.csv` в `exports/<run-id>/`.

Исторический пример: `python scripts/forecast.py --mode dataset --origin 2026-02-01T00:00 --days 28 --horizon 48`. Нужна история, заканчивающаяся 31 января 2026 года. Добавленные позже фактические данные запрещают запуск с origin раньше конца загруженной истории.

## Артефакты расчёта

| Файл | Содержимое |
|---|---|
| input.csv | Снимок измерений для запуска |
| request.json | Режим, origin, horizon, число повторов |
| weather-config.json | Координаты и часовой пояс |
| weather-live.json | Ответ текущего API, URL и время получения |
| weather-training.csv | Числовая архивная погода для обучения |
| weather.json | Источник, режим, URL, время получения, хеши и ячейки сетки |
| weather-forecast.json | Погодные значения для целевых часов |
| *.cbm | Обученные и проверочные модели |
| result.json | Прогноз, метрики, параметры, решения и SHA-256 измерений |
| replay.csv | Все прогнозные моменты и целевые часы |
| worker.log | Диагностика Python |

Артефакты находятся в `runtime/runs/<id>/`. Резервная копия приложения включает их и SQLite. Кеш API можно загрузить заново; резервная копия не содержит зависимости или программу.

Повтор текущего расчёта получает новую погоду, поэтому результат может отличаться. Для сравнения фиксируйте ID запуска, версию кода, хеш входа и погодные снимки. Зафиксированные зависимости и seed уменьшают различия, но побитовая идентичность вычислений на разных CPU не гарантируется.

## Данные в репозитории

`data/raw/` — необязательный локальный каталог, исключённый из Git. В публичном наборе есть только маленький `data/demo/turbine.csv` и генератор полной истории `ml/synthetic.py`. Погодные данные обычного режима атрибутируются Open-Meteo / DWD. MIT проекта не распространяется на исходный датасет и сторонние данные.

Проверка публикации: после добавления файлов в Git index выполните `python scripts/check_publication.py --history`. Проверяются staged-файлы и все локальные коммиты: приватные пути и распространённые форматы секретов. Проверка не очищает историю и не заменяет просмотр staged diff. CI загружает полную историю через `fetch-depth: 0`.

## Кеш моделей и резервные копии

`runtime/models/` хранит пакеты с проверяемыми SHA-256 и атомарно обновляемыми указателями. На каждом запуске модели, `training-report.json` и `weather-training.csv` копируются в каталог задачи; результат указывает `bundle_id` и `reused`. Резервная копия включает артефакты задач и базу. Отдельный кеш моделей в архив не включается: после восстановления на новой установке первый расчёт обучит модели заново. На той же установке совместимый проверенный кеш может использоваться повторно.
